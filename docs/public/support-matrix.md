# Alpha support matrix

Support has three independent dimensions: the protocol may define a concept, the current TypeScript runtime may implement it, and specific environments may have executable verification evidence. The generated README table and this document cannot strengthen the manifest selected by `support/current.json`. The historical `support/alpha-0.1.json` remains the first public support record.

Published `0.2.0-alpha.1` support is React Web, Node.js ESM, native browser WebSocket/Node `ws`, the PostgreSQL storage-v2 reference profile, typed `stateStream()` materialization, framework-owned command transactions, browser/server dependency isolation, and the separately installed local MCP companion. The package exposes ESM `import` conditions only; CommonJS `require` is not supported in this alpha. Release verification covers Chromium, Firefox, and WebKit. The 100-client Node workload is an environment-fingerprinted regression alarm, not a production SLO or capacity statement.

Session resume restoration, in-session auth refresh, foreground stale-transport replacement, production IdP refresh/revocation, a live production MCP service, general durable evidence aggregation, PostgreSQL replication/failover, and comprehensive exactly-once behavior are not alpha claims. The actual recovery path is cursor replay plus stable command-status reconciliation.

Socket.IO, vendor-neutral telemetry, Sentry, OpenTelemetry, React Native, Go, durable diagnostics export/storage, and an authenticated/authorized/audited production MCP query service are committed post-alpha work without dates. The release's portable manifests and framework-neutral transaction and diagnostic ports are extension boundaries, not claims that those future adapters already exist. Presence, Redis, NATS, and Kafka are demand-gated architecture candidates, not committed roadmap items.
