# Production deployment boundary

The alpha server terminates plain HTTP/WebSocket and is intended to run behind a TLS reverse proxy. The proxy owns certificates and WSS, must preserve `Upgrade`, `Connection`, `Sec-WebSocket-Protocol`, and `Origin`, and must set idle/read timeouts longer than the configured application heartbeat interval plus timeout. Proxy probes use `GET /health`, whose complete default body is `{ "status": "ready" }` with HTTP 200 or `{ "status": "unready" }` with HTTP 503. Runtime identity and dependency topology are deliberately absent. Detailed inspection, evidence, and chaos endpoints exist only in the explicitly enabled repository test control plane, are default-off, are not reachable through the public server facade, and must never be exposed as a production management API.

Every browser deployment must configure exact canonical HTTP(S) origins with `originPolicy.allowedOrigins`. `null`, malformed, wildcard, suffix, substring, credential-bearing, path-bearing, and non-HTTP(S) origins are rejected before authentication or a client slot is acquired. Origin-less Node `ws` connections are accepted only with explicit `allowMissingOrigin: true`; that opt-in must not be used as a substitute for browser Origin checks. Origin is an additional browser boundary, not authentication or authorization.

Set explicit per-gateway connection, subscription, inbound queue, inbound message-rate, application-hook, outbound buffered-byte, and drain limits. Invalid, non-finite, or disabled limits are rejected at construction; `drainTimeoutMs` is an integer from 1 through 300,000 ms, initiates the close handshake immediately, and force-closes a non-cooperating peer at the configured deadline. Full connection capacity returns HTTP 503 before WebSocket upgrade. Configure the client `connectTimeoutMs` so a black-holed handshake releases its pending socket, and `sessionOpenTimeoutMs` so a peer that upgrades but never resolves the session cannot wedge recovery. Both deadlines accept integer values from 1 through 300,000 ms. Custom reconnect schedules must contain positive, bounded, non-decreasing integers; zero-delay reconnect storms are rejected. Session establishment failures retain exponential half-to-full jitter until `session.ready`; only that stable boundary resets the attempt counter. Readiness is false until exact schema binding, database health, LISTEN, and the outbox publisher path are ready. During drain or database loss existing sessions receive bounded retry/failure behavior and cannot claim durable replay/snapshot/command success.

Alpha fixture authentication is not a production IdP integration. Cookie authentication requires the same fail-closed Origin policy; bearer/session-open authentication still requires it for browser clients. A bounded authentication timeout or hook-capacity failure returns a generic retryable response, while actual credential rejection remains non-retryable and non-enumerating. Refresh/revocation integration is not verified in this release line.
